Nothing today defines what a directed note is addressed to. The 2026-08-12 design never reached it; the 8/11 run faked the recipient inside one session. Substrate already exists: the live capture hook writes session_id, cwd, and kind (claude-session/grok-session) per prompt to the lake. Settle the address space before T1 fixes a record shape.

Decided 2026-08-15: cwd-selected, id-resolved. Sender picks by project directory; the stored note carries the resolved session_id plus the cwd it was chosen by. Remaining work: the resolver, and the tiebreak when two live sessions share a cwd.

Decision (2026-08-16): three address-space calls, all resolved with Levi.

1. Liveness — no filter. Every registered session stays resolvable, ranked by most-recent registration. The roster has no SessionEnd hook, so "live" is unknowable; and T16 (drain at session start) means a note to a dormant session is delivered when it wakes, not lost. Staleness policy stays out of T6.
2. Tiebreak — newest wins, ambiguity surfaced. resolve() returns the most recently registered match plus the full candidate list, so T3 can warn or offer a pick. Never blocks, never hides that a choice existed.
3. cwd match — normalized realpath exact first, else nearest-ancestor. An address of a repo root matches a session in a subdir when nothing matches exactly; dev worktrees nest sessions too deep for exact-only to be usable.
