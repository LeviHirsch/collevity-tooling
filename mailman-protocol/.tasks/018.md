Each live session keeps a small published view of itself in the shared cache and updates it as it goes, per the 2026-08-12 design (raw prompt 9): 'each turn there is a check with some sort of cache that says do I need to update myself to any other context'. T13 registration writes one line at SessionStart and never again; this is the updating half. The published views are the surface a sender or the Haiku switchboard reads to select a recipient - there is no name or folder addressing. Liveness falls out of this for free: a session that stopped updating is a session that stopped. Open: what one view carries, and what triggers an update.

Decision (2026-08-17, Levi): a view carries mechanical identity (session_id, cwd, kind, updated_at) plus three semantic fields - main topic (whole-session summary title), a general description/recap, and a short what-I-am-working-on - updated as needed as things change rather than on every trigger. Decision: updates fire on both UserPromptSubmit and Stop, so a session in a long autonomous run keeps its view fresh instead of reading as stopped; writing a view needs no stdout, so this does not depend on the T14 injection spike. Decision (agent call): views live at ~/.collevity/cache/mailman/views/<session_id>.json, one file per session rewritten in place - disposable per the lifetime rule, no append reduction needed, and staleness is mtime, which is what the liveness rule reads.

Decision (2026-08-17, Levi): the session self-reports its semantic fields - its own agent calls a small CLI when topic or focus changes. No LLM on the prompt path, no dependency on the T5/entry-router reconciliation, and it degrades gracefully: with no report the mechanical fields still refresh, so liveness still works.

Shipped (2026-08-17): bin/mailman_view.py publishes one view per session at ~/.collevity/cache/mailman/views/<session_id>.json, rewritten through a temp file and os.replace so a reader never catches a half view. Mechanical fields (session_id, cwd, kind, updated_at) are refreshed by the hooks; the semantic three (topic, recap, working_on, plus reported_at) are written only by the session's own agent via 'mailman_view.py report', and touch() is tested to never clobber them. Both triggers wired: UserPromptSubmit rides the existing mailman_check.py rather than adding a fourth interpreter start to the live prompt path, and a new bin/mailman_publish.py covers Stop. 17 new tests, 58 total green, plus an end-to-end smoke run across both envelope shapes. Diverged from the plan in one way worth naming: AGENTS.md is created here instead of being lifted from the closed T6 branch as T17 planned - the repo had no invariants file and three of them (hook imports are part of the fail-open contract; shared files append while owned files replace; the mechanical/semantic author split) were established by this work. T17's note is updated so it folds rather than re-creates. Knowingly left out: no staleness threshold - age_seconds() reports and the send side (T3) decides what is too old, since that was never ruled on; neither hook is installed in settings.json, same as T7 and T13, because that touches the live prompt path and is Levi's call; and the CLI's session self-identification (--session, then CLAUDE_SESSION_ID/GROK_SESSION_ID, then the lone view in this directory, refusing rather than guessing when two sessions share it) is untested against a live harness - whether either env var is actually exported is unverified.

Correction (2026-08-17, Levi): liveness is the concern, not staleness - and this task's earlier claim that 'liveness falls out of this for free: a session that stopped updating is a session that stopped' is FALSE. Both triggers only fire on activity (a prompt, or a turn ending), so a session left open for days is stale and fully alive. Sessions are sometimes open for days. Any staleness threshold would therefore declare long-lived idle sessions dead. What the fail-immediately ruling actually needs is a signal that a session ENDED, not evidence it was recently busy - and no such mechanism exists yet. Nothing shipped encodes the bad proxy: age_seconds() reports a number and asserts nothing about liveness, and no threshold was written. T3 must not build a live/dead test on view age.

Shipped (2026-08-17): Stripped the liveness-from-age language out of AGENTS.md and the view/hook comments: age_seconds() is last activity, not a live/dead signal, and T3 must not refuse a recipient because the view is old. Isolated mailman_check.touch() so a failed view write cannot skip T2, with a test that the debug breadcrumb still fires when the cache is unwritable. 59 tests green.
