Each live session keeps a small published view of itself in the shared cache and updates it as it goes, per the 2026-08-12 design (raw prompt 9): 'each turn there is a check with some sort of cache that says do I need to update myself to any other context'. T13 registration writes one line at SessionStart and never again; this is the updating half. The published views are the surface a sender or the Haiku switchboard reads to select a recipient - there is no name or folder addressing. Liveness falls out of this for free: a session that stopped updating is a session that stopped. Open: what one view carries, and what triggers an update.
