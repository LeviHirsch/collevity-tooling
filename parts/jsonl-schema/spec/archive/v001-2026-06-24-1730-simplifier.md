# Simplifier Critique — JSONL Schema Spec — v001 (Revision 3)
> Date: 2026-06-24 | Reviewer: Simplifier persona

---

## Pass 1: Component catalog

19 leaf ACs across 4 groups (AC1: 8, AC2: 3, AC3: 2, AC4: 6), 7 constraints, 4 success criteria, 4 open questions, 2 phases.

---

## Pass 2: Challenges

**AC1.6 — `claude-session` context shape**
The hook channel doesn't exist. The AC says it's "reserved in v1, not validated." If it's not validated, it's not a testable criterion — it's anticipatory infrastructure. The spec's own out-of-scope section excludes the hook capture surface. Define `context` as an optional freeform object (AC1.5 already covers optional fields); document the reserved shape in an implementation note, not the AC tree.

**AC1.8 — Excluded-fields list**
This is a negative spec — a list of fields *not* in the schema. The Out of Scope section already enumerates every one of them (entity_axis, kind, lineage_id, tier, modified, occurred_at, planned_for, horizon). AC1.8 duplicates it. A schema document that omits fields doesn't need an AC asserting their absence; the schema *is* the proof.

**AC1.7 — meta_notes convention**
The spec states the append-only, ISO-timestamp convention is "a convention, not a validated constraint." Then it cannot be independently tested. Cut the convention from the AC; drop a note in the schema document. The rest of AC1.7 (tags as free-form array, source_data as schema-on-read) is load-bearing and stays.

**AC2.3 — No scattered raw file reads**
This enforces an architectural rule, not an outcome. It's a constraint (already captured in the Constraints section: "accessed only through a thin storage seam"). Not independently testable without an audit pass. Demote to the Constraints section; remove from the AC tree.

**AC4.6 — Read-time ingest cadence**
"On-demand at read-time, piggybacking `read_day`" prescribes a solution. The real requirement is: idempotent, no daemon/cron during the transition window. How ingest gets triggered is an implementation detail. Rewrite or demote to an implementation note.

---

## Pass 3: Minimum viable cut list

Five removals: AC1.6, AC1.8, the meta_notes convention clause in AC1.7, AC2.3 (demote to constraint), AC4.6 (demote to implementation note). That drops the AC count from 19 to 14 without touching any testable outcome.

---

## Pass 4: Over-specification flag

AC4.6 is the clearest offender — it names a mechanism ("piggybacking `read_day`") inside an AC. The spec should demand the property (idempotent, no daemon), not the wiring.
