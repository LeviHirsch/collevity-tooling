## D-003 — Excel freshness has exactly one trigger: `/checkin`. Skip check-ins and the lake silently drifts.
- First seen: 2026-07-27 (Levi's hypothesis during an orchestrator pass; verified same session)
- Last touched: 2026-07-27
- Defer count: 0
- Category: feature (freshness / ingest triggering)
- Description: `sync_sources()` — the only thing that pulls the Excel Dropper into the lake — is called from exactly one call site, `collevity/lake/cli.py::main` (the read CLI, line ~41). That CLI is invoked only by `/checkin`'s `read_lake_day.py` launcher. Grepping every skill, `~/.claude/settings.json`, and `02_CONTENT/entry-router/` for any other caller of `sync_sources` / `lake.cli` / `read_lake_day` / `collevity-read-day` returns only the three checkin files. So Excel rows reach the lake **only as a side effect of running `/checkin`** — no check-in, no ingest, no warning. Give Excel freshness a trigger that does not depend on remembering a ritual.
- Notes: **Observed drift, 2026-07-27:** 55 Excel rows (2026-07-23 → 07-27, including all 47 from that day's 16:38–17:06 planning dump) existed only in `Dropper_excel.xlsm`; `excel-ingest-state.json` mtime 2026-07-23 00:21 = the last check-in, not a failure. Read them by unzipping the xlsm and parsing `sheet1.xml` directly.
  **This is a consequence of DEC-019, not a bug.** Making the *consumer* own freshness ("pull, then read") is good seam design; the gap is that `/checkin` became the only consumer that goes through the seam, so a read-path decision quietly became the write path's sole heartbeat.
  **Two structurally distinct problems. (P1) Coupling runs the wrong way.** The entry-router self-maintains via the `SessionStart` hook and needs nothing from Levi; the `UserPromptSubmit` hook captures Claude prompts automatically. So the two automatic channels carry *Claude's* traffic while the one needing a deliberate ritual carries Levi's own voice — the highest-value channel is the only fragile one. Note this is the same failure shape as [[entry-router]]'s TCC blocker, and its solution may transfer: a `SessionStart` hook runs in Levi's context and dodges TCC, so `sync_sources()` could ride the same lever the router already uses. Cheap candidate: have the router's `catchup.sh` call the seam (`collevity-read-day` or `sync_sources()` directly) *before* reading the lake — one line, makes the second consumer compose freshness the way DEC-019 intends, and both channels become automatic. Watch the Excel file-lock case (the CLI already treats a failed pull as non-fatal) and the openpyxl venv dependency.
  **(P2) The router reports success over a stale lake.** `route.py` reads the lake JSONL directly, bypassing the seam, so it never pulls. Its 2026-07-27 catch-up run reported 1720 reads and 0 errors while five days of Excel entries were missing — nothing in the output distinguishes "caught up" from "caught up on a stale lake." Even after P1, consider a staleness signal (compare newest Excel row timestamp vs newest `dropper-excel` entry in the lake, or surface `sync_sources`' `entries_ingested` where a human sees it) so silent drift is loud next time.
  Levi's framing: plan this into one of the dev threads rather than hot-fix it. Nearest live registry row is `entry-router`; may equally belong to a part-1 (jsonl-schema) iteration alongside D-001.
  **Complement (not a fix) — 2026-08-01 `grok-capture-path`:** shared `capture_prompt.py` now accepts Grok camelCase envelopes (`source: grok-hook`) as well as Claude (`claude-hook`). Grok was already invoking the Claude wire-up via settings compat; only snake_case field reads blocked it (sidecar showed `sessionId` failures). Agent-drop ritual path retired. Still does **not** resolve D-003 for Excel rows — that stays P1/P2 / `capture-health` + `dropper-capture-durability`.

## D-002 — Hook authorship integrity: `author:user` is stamped blindly on all UserPromptSubmit captures
- First seen: 2026-07-13 (iteration 1, via Levi post-install consideration)
- Last touched: 2026-07-13 (iteration 1)
- Defer count: 0
- Category: feature (hook iteration 2)
- Description: The hook hardcodes `author: "user"` on every capture, but `UserPromptSubmit` fires for non-human submissions too, so the label is an unverifiable claim. Uphold the "user-written context only" intent by distinguishing genuine user authorship from AI/programmatic submissions.
- Notes: **Verified fact pattern (2026-07-13; CLI 2.1.208, claude-agent-sdk 0.2.117):** interactive human session → captured correctly; **Task-tool sub-agents (spawned within a session) → do NOT fire the hook (safe — re-verified post-install with the hook LIVE: a marked sub-agent probe added zero lake entries; the earlier pre-install evidence was invalid, Levi caught it)**; headless `claude -p` → fires, stamps `author:user` regardless of launcher (proven: HOOK-ROLLOUT-TEST, an AI-launched session); **Agent SDK `query()` → FIRES the hook, including with `setting_sources=None` (default) AND `setting_sources=["user"]` — both captured as `author:user`; only `setting_sources=[]` (explicit empty) is hermetic and skips it** (empirically tested). This makes P2 material — the [[claude-account-switcher]] project is explicitly about launching SDK agents concurrently, so those would all pollute the lake unless mitigated. AI-drafted text a human pastes+sends → fires as `author:user`, hook cannot detect it's AI-drafted. Docs: the payload (session_id/prompt_id/transcript_path/cwd/permission_mode/hook_event_name) has **no field distinguishing human vs programmatic**, so the hook can't self-detect. **Two structurally-distinct problems: (P2) programmatic/agent SESSIONS** — two mitigation levers: (a) **available today, zero hook change:** SDK launchers pass `ClaudeAgentOptions(setting_sources=[])` → hermetic, no capture — but that also drops ALL other user settings (permissions/model/etc.), so it's blunt; (b) **hook iteration 2 (surgical):** hook reads `COLLEVITY_HOOK_AUTHOR` (default `user`) and/or `COLLEVITY_HOOK_SKIP`; SDK launchers set it via `ClaudeAgentOptions(env=…)`, `claude -p` launchers via the process env — burden on the few automation entry points, not every prompt (hooks inherit launcher env; the settings.json command doesn't set these vars, so a launcher value passes through). **(P1) AI-drafted text submitted in a human session** — irreducible at capture; either a creation-time marker attached by the ~few prompt-generating tools, or (preferred) defer authorship-refinement to the future triage/contextualize layer (aligns with DEC-002/004: typing/promotion live downstream of the raw entry). Candidate = **hook iteration 2** (+ maybe a part-1 `author` vocabulary decision: user/agent/unknown).
