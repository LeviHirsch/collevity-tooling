# Interview — Prompt-Capture Hook (Dropper Pipeline op-path slot 3)

Date: 2026-06-29
Mode: greenfield

## Grounding (carried in from prior work — not yet user-confirmed)

- **Part role:** op-path slot 3 of the Dropper Pipeline. Capture surface that
  writes session-side drops into the live lake via `append_entry`. Keystone
  (JSONL schema, part 1) is **built + live**; lake at `03_TACTIC/_DATA/collevity_lake.jsonl`.
- **Store contract (already fixed by part 1):** a capture surface calls
  `append_entry({text, created_at, source, author, ...optional})`; the store
  mints `id` (UUIDv7), validates, appends. Surface does NOT mint id.
- **Schema decisions that pre-shape this part:**
  - DEC-002: `author` = `user` in v1 even for Claude-prompt drops. `source:
    claude-hook` is the channel tag. So attribution-by-author is NOT v1's job.
  - Reserved `context` shape for this source:
    `{ kind: "claude-session", session_id, seq, parent_id? }`. Becomes
    **conditionally required** for `source: claude-hook` entries — that
    conditional validation is THIS part's work.
  - `source_data` is the reserved lossless stash; first populator = the
    claude-hook session payload.
  - `created_at` must carry the correct local offset, stamped at capture
    (DEC-017) — the hook owns its own offset.
- **Open from the old stub (3_prompt-capture-hook.md):** trigger model (explicit
  / auto-triage / at-session-save), triage filter, attribution chain for mixed
  user+AI, relationship to `/session-save` SPP bundle.

## Socratic interview

### Q1 — What IS this part, given the schema demoted author→user? (a thin channel / b capture+triage / c session harvester)

**Levi [from-user]:** Still distinct from the mobile shortcut. The goal is
**user-driven entry extraction**. v1 = just the hook: **collect ALL entries**.
Later add a triage layer — (b) — OR *contextualize non-understandable solo
inputs*. Also floated: use this as a **first test of SDK** things ("trying my
hand at an SDK call").

**Reframe captured:** the hook captures the user's *prompts*, which are often
**conversational fragments** — terse, context-dependent, not self-contained like
a mobile drop. That fragment-nature is the real distinction from the shortcut,
and it's why the later layer must **contextualize**, not merely triage.

**Claude's position on the SDK (answer to "what do you think?"):**
- Layer separation: a Claude Code **hook** = shell command on `UserPromptSubmit`;
  for "collect all" it's pure plumbing (stamp offset → `append_entry`), **no LLM**.
  An SDK call inline would add latency/cost/failure to every prompt and can't fail
  open without dropping data → wrong place.
- The **SDK belongs in the triage/contextualize layer**: genuinely LLM-shaped,
  and should run **async/batch over the lake** (P4: queued drop must not block the
  session), not inline.
- Recommended split: **v1 hook** = dumb/deterministic/fast (ships soon); **SDK
  test** = standalone script over the lake, later iteration of this part (or
  sibling). Pin API specifics (model id, package) when that layer is spec'd.
- **CONFIRMED (Q3): v1 carries no SDK; SDK → later triage/contextualize layer.** (DEC-001)

**Levi [from-user]:** Doesn't want to blanket-filter hook entries out of checkin —

**Insight captured:** the value isn't only individual keeper-drops — it's the

### Q6 — Non-blocking constraint + what each entry carries under global scope

**Claude assertion (Levi accepted):** hook must be **fail-open / non-blocking** —
a lake-write failure must never delay or block prompt submission. (Levi: triage
layer will also run behind-the-scenes after the prompt passes — same principle.)

**Entry payload [from-user]:** all three — `text` + `created_at` + `context`.
- **cwd belongs in `context`, NOT `source_data`** (Levi corrected Claude): cwd is
  *designed* context for this source. v1 context shape:
  `{ "kind": "claude-session", "session_id": …, "cwd": … }`.
- **Thread-discrimination caveat (Levi):** cwd doesn't separate the
  dropper-pipeline thread from the CAS thread (shared roots). **Resolved:** that's
  *semantic* and is **part 4 (thread-extraction)'s** job, not the hook's. The hook
  captures raw signal (text + session_id + cwd + timestamp); part 4 clusters.
  Levi: "good point on semantic threading. I accept that for the most part."

### Q7 — Drop `seq`?

**Claude:** `seq` = prompt's position-in-session. Drop for v1: redundant with
`created_at` + UUIDv7 `id` for ordering; not free (hook would have to count prior
same-session entries in the hot path); derivable later. **Levi: "skip seq is
great."** → seq reserved, not populated.

### Q8 — Two small edges (Claude leans, taken unless objected)

- **Slash-command inputs** (`/checkin`, `/spec …`): **capture them, no skip-list**
  — a skip filter is itself triage (deferred). Dumb hook captures whatever
  `UserPromptSubmit` delivers.
- **`source_data` in v1**: **leave empty.** Everything useful is in `context`;
  full transcript is derivable from `session_id` + `cwd`
  (`~/.claude/projects/<encoded-cwd>/<session_id>.jsonl`), so no need to store a
  fragile path. `source_data` stays reserved.

## Conclusion

- **Goal:** a global Claude Code `UserPromptSubmit` hook that appends every user
  prompt to the lake via `append_entry` — deterministic, fail-open, no LLM in the
  path. (DEC-001, DEC-002)
- **Constraints:** fail-open / non-blocking (a lake-write failure must never delay
  or block prompt submission); zero field-contract change (writes only
  already-accepted fields: `text`, `created_at`, `source`, `author`, `context`);
  global scope via `~/.claude/settings.json` (DEC-005); `created_at` carries the
  correct local offset stamped at capture (DEC-017 from part 1).
- **Success criteria (lightest axis — tighten in seed):** prompt submitted →
  matching entry lands in the live lake with `text` + `created_at` (correct
  offset) + `context {kind: "claude-session", session_id, cwd}`, `source:
  claude-hook`, `author: user`; session is never blocked on write failure;
  `/checkin` day-read surfaces the entries unfiltered (DEC-003).
- **Scope boundary (out):** triage / promotion (DEC-002, DEC-004), contextualize
  layer, any SDK/LLM call (DEC-001 → later async layer over the lake), `seq`
  (reserved not populated), `source_data` population (reserved, empty in v1),
  semantic thread-discrimination (part 4's job), slash-command skip-lists.
- **Root-vs-symptom:** root = user-driven entry extraction; the value is the
  **timestamped flow / shape of attention over time** that thread-tracking reads
  from the raw lake — not merely individual keeper-drops.
