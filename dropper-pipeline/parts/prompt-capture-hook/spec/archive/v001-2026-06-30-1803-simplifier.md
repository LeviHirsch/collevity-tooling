# Simplifier critique — prompt-capture-hook spec.md v001

## 1. Catalog
AC1 (install: 1.1–1.2), AC2 (payload: 2.1–2.6), AC3 (persistence: 3.1), AC4
(fail-open: 4.1–4.2), AC5 (readability: 5.1). Plus 2 implementation phases and
4 open questions.

## 2. Challenge each component

This spec is already lean — DEC-008 already cut `seq`/`parent_id` from the
context shape, and DEC-001/002 already rejected inline triage and
session-harvester alternatives. Little fat remains, but two items still earn
scrutiny:

- **AC2.6 ("no `id`, no `source_data`, context carries only kind/session_id/cwd").**
  This is a negative assertion bundled onto a positive-payload group. It's not
  a separate concern from AC2.1–2.5 — it's the contrapositive of "context is
  exactly this shape." Could fold into AC2.5 as a closing clause ("...and no
  other keys") without losing testability. Minor, but it's the one AC that
  reads as a defensive restatement of the contract rather than a new
  requirement.

- **AC5 / Phase 2 as a whole.** AC5.1 (`read_day` surfaces the entry with
  correct time bucket) tests *part 1's* `read_day`, not anything the hook
  itself writes beyond what AC2.2/AC3.1 already pin down (correct offset,
  valid JSON line). If `created_at` has the right offset (AC2.2) and the line
  validates (AC3.1), `read_day` surfacing it correctly is a part-1 regression
  concern, not new hook behavior — DEC-003 explicitly says part 1 isn't
  touched. AC5.1 is good integration insurance, but it's the one AC that
  isn't testing the hook's own write path — it's testing the read path's
  consumption of the hook's write. Defensible to keep (catches offset bugs
  empirically) but it's the most cuttable single leaf if Phase 2 needs to
  shrink.

## 3. Minimum viable spec / cut list

If forced to cut half: keep all of AC1–AC4 (these are the actual hook
contract — install, payload, persist, fail-open). Cut AC5.1 / Phase 2
entirely. The hook's job ends at "valid line in the lake with the right
fields" (AC3.1 + AC2.*); proving `read_day` reads it back is duplicate
coverage of part 1's existing read contract. This isn't a recommendation to
cut — Phase 2 is cheap (one manual run) and catches integration drift — but
it is the one phase whose absence wouldn't leave the hook's own goal
unverified.

No other AC is a candidate; AC1–AC4 each test a distinct, load-bearing
mechanism (file exists+wired, fields correct, line persisted, never blocks).

## 4. Over-specification

None found. The spec resists prescribing solution shape: "stable absolute
path" (not a specific directory), "the implementer decides" on language
(open question 3), no mandated venv/PYTHONPATH approach (open question 4).
Constraints state requirements ("fail-open," "zero field-contract change"),
not implementations. No flag here.
