# Simplifier critique — prompt-capture-hook spec, rev 3

## 1. Catalog
Sections: Open questions (x2, top+bottom), Cross-part deps, Goal, Constraints (6 items incl. 2 "accepted risk" sub-bullets), Success criteria (3), Out of scope (9), AC1–AC5 (17 leaves + 1 demoted implementation note), Implementation phases (2).

## 2. Challenge

**Duplicate "Open questions" section.** It appears in full at the top (lines 7–15) and again as a one-line pointer at the bottom (lines 126–128). The bottom section adds zero information — it only says "see top, all resolved." For a spec that's converged (all 4 resolved, no open items), this is a vestigial scaffold from the interview phase. Cut the bottom stub entirely; nothing breaks.

**Success criteria section duplicates the AC tree.** The MECE note on the AC tree explicitly states "every guarantee-level success criterion above traces to at least one AC leaf" — so by the spec's own admission, Success Criteria and AC1–AC5 encode the same three guarantees twice, once in narrative form and once as testable leaves. For a spec this far converged, carrying both is pure maintenance surface: any future edit to a guarantee now requires updating two places to stay in sync (and they're not — the AC tree already covers the sidecar-diagnostic mention that Success Criteria also re-describes in a parenthetical). Recommend deleting the Success Criteria section and letting Goal → AC tree be the single source of truth. If a plain-English summary is wanted, it belongs in Goal, not as a parallel spec structure.

**`COLLEVITY_HOOK_ERRLOG` override is infrastructure for a hypothetical.** The AC4 implementation note grants the sidecar breadcrumb a configurable path via env var override — but the sidecar itself is explicitly non-AC (DEC-017, deliberately kept as best-effort, not a guarantee). No AC or success criterion exercises a custom errlog location; nothing in the goal or constraints motivates why the path needs to be overridable. This is solving a problem nobody asked for (what if the default path is wrong for someone) rather than the stated problem (capture prompts, fail open). Cut the override; hardcode `hook/capture_errors.log` beside the script. If a real need for relocation shows up later, add it then.

**Open question 2's rollout-check caveat is now stale.** The instruction "the implementer should echo the raw stdin payload once to confirm key names" was a pre-implementation caveat. Implementation landed 2026-07-11 (commit 606d1c4) and the shipped script already "accepts both keys" per the same sentence — so the caveat has been executed and superseded by the code. Keeping the procedural instruction in the spec after the fact is dead weight; it reads as an implementation note that belongs in INSTALL.md's rollout section, not spec.md.

## 3. Minimum viable spec
The AC tree itself (17 leaves) is already lean — each leaf maps to a distinct field/behavior needed for a plumbing hook, nothing there is gold-plated. If forced to cut, the deletable material is entirely outside the AC tree: the duplicate Open Questions stub, the Success Criteria section, and the ERRLOG override — none of which are tested by any AC.

## 4. Over-specification
None of substance beyond the ERRLOG override above — the rest states requirements, not solutions.
