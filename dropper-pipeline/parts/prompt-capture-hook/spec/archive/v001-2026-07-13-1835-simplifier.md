# Simplifier — Third (Convergence-Confirming) Pass, Rev 5

Scope: only the three Rev-5 additions. Prior cuts (DEC-020) not re-litigated.

## 1. Catalog of Rev-5 additions

- Constraints → new accepted-risk bullet: **torn-write on kill (DEC-021)**.
- AC4 → new **scope note** (external termination vs. in-process exception).
- AC1.1 → new clause naming the installed **timeout value** (10s, bound by 30s default).

## 2. Challenge each

**DEC-021 (torn-write bullet).** Carries three distinct, non-restatable facts: the mechanism (kill mid-flush → partial JSONL line), the consequence (part-1's `_read_all` raises, breaking reads until repaired), and the probability/layer reasoning (low-probability, inherent to any synchronous stall-capable hook, real fix is part-1's and already tracked as D-001). Nothing here is decorative — each clause blocks a different reviewer objection ("why not just raise the timeout," "isn't this hook's job to fix," "how bad is this really"). Load-bearing. No cut.

**AC4 scope note.** Without it, AC4.1's claim ("hook swallows it and exits 0... never blocked, delayed, or erased") would silently overreach into territory the hook can't guarantee — a signal-kill isn't an in-process exception, so AC4.1 as a unit-testable AC needs the boundary stated or it's untestable as written. The note also does real MECE work: it explicitly cross-refs how AC3.1 already scopes out concurrent-append integrity, so the pattern reads as one convention rather than two ad hoc carve-outs. Necessary for AC4 to stay independently testable. No cut.

**AC1.1 timeout-value clause.** This isn't prescribing a solution — Phase 1 is already code-complete and the value (10s) is already installed. Stating the actual installed number, bounded by the documented 30s platform default, is the requirement made checkable (AC1.1 has to assert *something* concrete about "bounded"). Omitting it would leave "a small number of seconds" untestable. No cut.

## 3. Minimum viable spec / cut list

No cuts. All three Rev-5 additions are either closing a testability gap in an existing AC (AC4, AC1.1) or supplying non-duplicative risk reasoning already scoped to a named deferred item (DEC-021 → D-001).

## 4. Over-specification check

None found. No addition prescribes an implementation where a requirement would do — the timeout value is a fact about what's installed, not a design mandate; the scope note draws a test boundary, not a mechanism; the DEC-021 bullet assigns risk ownership without proposing a fix.

**Verdict: no new over-specification; appropriately lean. Converged.**
