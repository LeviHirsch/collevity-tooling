# Ontologist Review — Rev 4 (second pass)

## 1. Essence
Unchanged: this is a durable, fail-open logging tap on a Claude Code lifecycle event. DEC-018's stall/timeout language and AC1.1's composability clause are both refinements of the "fail-open" essence, not additions to it — they describe *how* fail-open holds up under a slow write and a shared hook array. No essence drift.

## 2. Root cause
No new issue. The root need (capture prompts without ever being in the user's way) is still the frame DEC-018 argues from explicitly ("delay — not fail").

## 3. Prerequisites
DEC-018 introduces a load-bearing but *unverified* prerequisite: that Claude Code treats a timeout-kill as a non-2 exit. The Constraints section says this plainly — "Claude Code's docs are silent on whether a timeout is specifically treated as blocking" — and treats the modest timeout as a hedge rather than proof. That's honest, but it means the spec is accepting an assumption about host behavior it cannot itself test. Nothing wrong with accepting it (Levi's call), but flagging it as a prerequisite worth a one-time rollout check (same pattern already used for the `user_prompt` key-name check in Open Question 2) would close the loop the same way.

## 4. Hidden assumptions
One genuinely new gap: **DEC-018 makes a testable claim with no AC leaf covering it.** AC4.1 covers exceptions raised *during* the write ("the lake write raises any exception... exits 0"); it does not cover the timeout/signal-kill path DEC-018 describes (Claude Code kills the command externally — there's no exception for the script to swallow, and no exit-0 to produce, since the process is terminated). The spec's own MECE claim ("Each leaf is independently testable") and exhaustiveness claim ("every guarantee-level success criterion... traces to at least one AC leaf") are both slightly oversold against this new constraint: DEC-018 is a guarantee-shaped statement (stall → delay, not block) but sits in Constraints with no corresponding AC or success criterion, and no test scenario for "hook exceeds timeout" exists (the write-failure success criterion tests a read-only path, not a stall). This is a small hole, easily closed by either (a) explicitly noting in AC4 that timeout-kill is out of AC4's test surface by construction (the way AC3.1 explicitly excludes concurrent-append line integrity), or (b) accepting it silently as untestable without live Claude Code instrumentation — either is fine, but right now the spec doesn't say which.

The AC1.1 composability clause introduces no new hidden assumption — it correctly scopes itself to installation mechanics (array append) and doesn't claim anything about execution ordering or concurrency semantics among co-installed hooks.

## 5. Phase dependency invariant
Phase ordering: no forward-dep violations spotted. AC1.1's new timeout language is still Phase 1 work; Phase 2 doesn't touch it.

## Most load-bearing concern
DEC-018 makes a claim (timeout-kill is non-blocking) that no AC leaf tests or explicitly disclaims — worth one sentence in AC4 saying whether that's intentionally out of scope or deferred to the rollout check.
