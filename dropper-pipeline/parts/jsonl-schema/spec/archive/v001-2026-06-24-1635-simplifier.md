## Pass 2. Challenges

**AC1.6 — claude-session shape.** Pre-specs `{kind, session_id, seq, parent_id?}` for a source that doesn't exist in v1 and is already deferred by out-of-scope ("capture surfaces… separate parts"). The optional `context` field is load-bearing; the embedded shape contract is not. This is infrastructure for a hypothetical channel. Cut the shape; leave the field.

**AC1.7 — meta_notes convention.** "Append-only, ISO-timestamp, newest-at-bottom, no-typed-prefix" is a style guide, not a schema constraint. Nothing downstream validates it. It will drift the moment a real consumer appears. Move it to a README or drop it; it doesn't belong in a testable AC.

**AC1.8 — exclusion documentation.** Requires verifying that named fields *don't* exist. The Out of Scope section already states these exclusions in prose. Duplicating them as a testable AC creates maintenance debt (keep two lists in sync) without adding a testable behavior. What test fails if AC1.8 is removed? None. Cut it.

**AC4.4 — MDT tz backfill.** Open question 1 admits the mechanism is unresolved. An AC whose implementation path is undefined can't be tested. This is a one-time migration runbook item, not a schema AC. Defer to a migration note; remove from the AC tree.

**AC4.6 — "piggybacks on read_day."** Specifies a mechanism (ingest runs inside read_day calls), not a requirement. The real requirement is: no daemon, no cron, idempotent within a session. How ingest is triggered is an implementation choice. Flag and restate as a requirement; drop the mechanism.

## Pass 3. Minimum viable cut list

Five items to drop without breaking the goal or success criteria (a–d):

1. AC1.6 claude-session shape (keep field, cut shape spec)
2. AC1.7 meta_notes convention (keep field definition, cut style rules)
3. AC1.8 (entire AC — exclusion docs belong in Out of Scope)
4. AC4.4 (defer to migration runbook)
5. AC4.6 mechanism clause ("piggybacks on read_day")

Estimated removal: ~20% of spec text, zero loss to core testability.

## Pass 4. Over-specification flags

- AC1.6: solution-shaped (full shape contract) where requirement is sufficient (optional typed context bag).
- AC4.6: mechanism-shaped ("piggybacks on read_day") where requirement is sufficient ("no daemon/cron, idempotent").
- AC1.7 meta_notes: style-guide-shaped where schema type is sufficient ("optional prose string").
