# Ontologist Critique — v001 — 2026-06-24

## 1. Essence

The spec calls itself a "JSONL schema and thin storage seam," but those are two distinct things: a field contract and a storage interface. The Goal section fuses them and further muddies the essence by foregrounding Excel replacement ("replaces the flat 3-column Excel Dropper"). Strip that away and the essence is: *define the canonical shape of a Collevity entry and the minimal read/write interface that enforces it.* Phase 1 delivers exactly this; Phase 2 is transition scaffolding. The spec would be cleaner if the Goal stated the enduring essence first and positioned Excel replacement as motivation, not identity.

## 2. Root cause

The stated goal is partially symptomatic. "Replacing Excel" is the trigger; the root need is a durable, source-agnostic truth record that every downstream consumer (checkin, threader, future strata) reads reliably. Phase 1 satisfies the root need whether or not Excel ever existed. AC4 satisfies the transition need. Both are real — but blending them in the Goal creates a spec that could be read as obsolete once the bridge is deleted, when in fact the core store is permanent.

## 3. Prerequisites

Two hidden dependencies are load-bearing but understated.

**`read_dropper_day.py` as parity target (AC3.1):** the script is a retiring artifact known to have tz bugs — that's why DEC-014 exists. Specifying that `read_day` must match its output risks cementing its quirks into the new store. The actual prerequisite is a *definition* of correct output, not parity with a buggy predecessor.

**MDT-row identification (AC4.4):** listed in Open Questions, but it is a blocking prerequisite for Phase 2 completion, not an optional note. A team hitting Phase 2 without this resolved cannot finish AC4.4.

## 4. Hidden assumptions

**AC4.2 row-identity scheme** assumes col E drop-timestamps are unique per row (with index as tiebreaker). If col E has nulls or duplicates beyond what the tiebreaker handles, the sidecar state file maps incorrectly and idempotency breaks silently.

**Optionality of `context` is source-conditional (AC1.5, AC1.6):** the spec marks `context` as optional globally, but for `claude-hook` source entries it is effectively required to carry `{kind, session_id, seq}`. A validator treating `context` as universally optional would pass malformed hook entries.

## 5. Phase ordering

AC3.1's success criterion (b) — actual `/checkin` parity for the same day — cannot be fully verified until Phase 2 supplies real Excel-ingested data. The AC is in Phase 1 (format verification), but meaningful parity validation is a Phase 2 concern. Mild forward dependency on verification, not on implementation.

---

**Most load-bearing concern:** replace the `read_dropper_day.py` parity target in AC3.1 with an explicit output definition — otherwise the new store's read contract is anchored to a known-buggy artifact.
